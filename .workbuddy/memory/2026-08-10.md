## /diary 接口 person 字段改用 identity_tag（而非 user ID）
- 需求：/diary 接口写入的 person 应为 identity_tag，不是 user ID
- 根因：`store/persons.js` `loadPersons()` 原本把 person.id 设为 user ID 字符串，导致 `date-detail-modal` 选中值、写入 /diary 的 person、聚合分组键全是 user ID
- 改动：
  - `store/persons.js`：`loadPersons()` 的 person.id 改为 identity_tag（自己=user.identity_tag、绑定用户=partner identity_tag），"共同" 仍为 'both'；删除不再使用的 `extractPartnerId`
  - `pages/index/index.vue`：AI 录入 `executeAiAdd` 原把 person 映射成遗留的 husband/wife/both 代码，改为 `resolvePerson()` 按当前人物列表解析为 identity_tag（精确匹配 id/name，兼容"老公/老婆/共同"别名，失败回退 both）
- 联动无需改：`store/calendar.js` 的 `addEvent`/`diaryToEvent`/`aggregateByPersonThenType`、`date-detail-modal` 的 personColor/personName、统计页均依赖 person.id，id 改成 identity_tag 后自动一致
- 风险：此前已写入的 person=user ID 的旧日记，按 identity_tag 分组时会 fallback 显示为"共同"+紫色（旧数据未迁移）
